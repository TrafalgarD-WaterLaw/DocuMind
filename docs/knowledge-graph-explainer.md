# 知识图谱在 DocuMind 中的作用（面试讲稿）

> 一句话：图谱是五路混合检索里唯一"不靠相似度"的确定性组件——解决关系型/枚举型/多跳问题的确定性与完整性。

## 一、三个实际用途（代码实证）

| 用途 | 实现 | 解决的问题 |
|---|---|---|
| 关系型问题精确回答 | `graph_query.py`：REL_WORDS 意图路由 + 6 个白名单 Cypher 模板（T1-T6）→ 图谱证据流式回答 | "叩鼎出土于哪里""妇好墓出土了哪些青铜器"——枚举/关系类问题 |
| 检索查询扩展 | `hybrid.py` graph 路：LLM 提实体 → `search_path` 查关联（≤5 个）→ 扩展词补一轮语义检索 | 问"妇好墓玉龙"自动补"商代""殷墟妇好墓"，提高召回 |
| 证据溯源 | sources 带 `graph_anchor`（entity/related/links 三元组）→ 前端渲染图谱子图 | 答案可溯源，显示"叩鼎—[属于]→商代"路径 |

## 二、解决 RAG 的根本缺陷

1. **关系盲区**：纯 RAG 按语义相似度召回——"哪些器物出土于殷墟"没有哪个 chunk 恰好罗列全部，必然漏；图谱一条 `MATCH (a:Artifact)-[:EXCAVATED_AT]->(s:Site {name:'殷墟'}) RETURN a` 精确返回全部。
2. **多跳推理**：文本检索只有一跳相似度；图谱能多跳——器物→朝代→同朝代器物、器物→遗址→同遗址器物。
3. **幻觉约束**：答案来自真实节点关系 + 白名单模板 + 规则回退，比 LLM 自由生成可信。
4. **查询理解辅助**：实体提取 → 图谱校验 → 扩展查询词。

## 三、业界对照

- 我们的做法：**领域预建图谱**（数据源自带关系：器物-朝代-窑口-遗址）——Knowledge-Grounded RAG / 混合 RAG（图谱+向量双通道），当前主流方向。
- 微软 GraphRAG（2024）：从文本自动抽取实体关系建图 + 社区检测 + 全局摘要——解决"全局性问题"（整个数据集讲了什么）。

## 四、诚实的局限（面试被追问时主动说）

- 图谱覆盖有限（青铜 2242 + 瓷器 70 + 河南 283 实体），实体不在图谱时自动降级文本检索。
- 图谱是"增强通道"不是"替代通道"——与向量检索互补。
