# 多模态 RAG 欠缺分析

> 2026-08-13 审阅产出——从"多模态 RAG 项目"视角盘点当前欠缺。
> 现状基准:CLIP 双塔 92% AnyHit@5 / 3821 图注块 100% VLM 描述 /
> 检索契约 Recall@8 100% / MRR 0.693。

严重度:🔴 面试会被深挖 / 🟡 值得做 / 🟢 讲清楚即无碍。

## 1. 入库(Ingestion)

- [x] ~~**VLM 描述无质量质检**~~(2026-08-13 已做):自动指标全量扫描——
  无法辨认率 4%(185/3820,合法空输出)、平均 24 字(<8 字 81 张 / >80 字
  1 张)、同源重复率 0%(无同质化)、实际零无描述残留;人工阅卷 24+ 张
  (窦泰墓志 10 + 镂空龙纹俎 14,会话过程中逐张读过)全部准确。
  工具:`scripts/audit_captions.py`(抽样报告)。
- [x] ~~**无增量更新语义**~~(2026-08-13 部分修复):真正的隐患是替换窗口
  非原子(先删旧再入库,入库失败时旧文档已丢)——已改"先建后删",失败时
  旧文档完好。**块级增量明确不做**:需块指纹 + 部分删除 + 问题索引联动,
  复杂度高,演示项目"删除重建"耗时可接受。
- 🟢 **仅 PDF**:文物文档场景可接受,面试一句话带过。

## 2. 索引(Indexing)

- 🔴 **双空间融合 vs ColPali 单空间(架构选择,非欠缺——面试答案)**:
  文本用 bge(512 维)、图片用 CLIP(512 维)两个独立空间;图片块在
  documents 里是 bge 编码的文本描述,clip_images 是 CLIP 编码的图像。
  为什么不选 ColPali(整页文档视觉向量,原生图文联合检索):
  1. **场景不匹配**:ColPali 解决"版面复杂的文档页"(图表/表格/多栏)
     的检索,依赖整页视觉信号;本项目的检索主体是**独立器物图**——
     每张图本身就是完整检索单元,没有版面语义可挖。
  2. **中文 CLIP 已有图文同空间**:Chinese-CLIP 让文找图/图找图天然
     可算余弦,这是 ColPali 想给的"原生联合"能力,已在 clip 路
     (第 6 路,参与 RRF)落地。
  3. **成本**:ColPali 要换模型/重建索引/改检索链路,收益无法量化。
  结论:双空间互补融合(bge 文本精确 + CLIP 视觉相似)是本场景的正确
  架构,clip 路进 RRF(2026-08-13)已把"拼装展示"升级为"融合检索"。
- [x] ~~**clip_images 增量异步后写**~~(2026-08-13 已修):fire-and-forget
  改 await 同步完成——documents 与 clip_images 上传结束即一致;失败时
  任务状态明确提示"CLIP 增量失败,图找文不完整"(此前只 warning,
  永久不一致且无感知)。CLIP 模型 prewarm 已预热,await 无时延顾虑。

## 3. 检索(Retrieval)——最大缺口所在

- [x] ~~**文找图不参与检索排序**~~(2026-08-13 已修):`_path_clip` 第 6 路——
  text_search 视觉命中反查文本/图注块参与 RRF。权重网格实验:0.3 →
  MRR 0.676 回归、0.1 → 契约恢复(100%/0.693)且真实生效(妇好鸮尊
  bm25+clip 双票浮上 top8)。已知边界:纯抽象视觉查询 CLIP 单票在
  0.1 权重下仍难进 top8——契约优先的保守取舍。
- [x] ~~**图片块召回深度受限**~~(2026-08-13 实验):直检 3→5 条无副作用,
  已保留;降权 0.3→1.0 实验(MRR 0.693→0.688,路径覆盖 86%→91%),
  "只降 semantic 单票"与全量 1.0 等价——证明 0.3 非残留防御,代价来自
  多票自然命中的图注块。维持全量 0.3(契约优先),实验数据留注释。
- [x] ~~**vision 查询理解不感知图片内容**~~(2026-08-13 已修):查询准备
  改用 CLIP top3 识别名候选构造多查询(复用 QueryPlan 多查询机制——
  逐个检索后合并,与文本问答拆解路径同款);top1 识别错时 top2/3 兜底。
- 🟢 **reranker 未在多模态场景评估**(2026-08-13 实验中止,最终结论):
  两轮实验均无法完成——①CPU 推理 18 分钟未完成;②显式 CUDA 后单次
  1.03s,但 bge+CLIP+reranker 三模型常驻 4GB 消费级显卡(显存 3.9/4GB
  触顶),eval 第 5 条查询起 GPU/CPU 满负载空转 67 分钟零产出(显存
  换页抖动)。维持禁用,结论以文本场景实验为准;
  面试口径:"cross-encoder 在文本场景网格实验全面退化(Recall -7.1pp/
  MRR -14%),多模态场景受限于 4GB 消费级显卡无法完成评估——工程上
  按'未验证即不启用'的原则维持禁用,多路加权 RRF 已足够"。

  (DashScope Qwen2.5-VL API 支持 bbox 输出,可做;待定)
- [x] ~~**图文对照展示弱**~~(2026-08-13 已修):证据卡升级图-文并排
  (图片列左 84px 竖排 ≤3 张 + 文本列右);回答正文引用 hover 弹出该源
  首图缩略图(固定定位浮窗,pointer-events 穿透)。
- [x] ~~**引用标注 [N] 与图片联动弱**~~(2026-08-13 已修):回答正文
  [N] 渲染为可点击金色徽章(仅助手消息,排除 markdown 链接误替换)→
  store.activeCitation → SidePanel 切对应轮次 → EvidencePanel 滚动定位
  + 高亮 2.4s。imageAbsUrl 提取至 utils/images.ts 共用。

## 5. 评估(Evaluation)

- [x] ~~**无混合模态评测**~~(2026-08-13 已建 `eval/vision_eval.py`):
  15 用例三域(河南 7/瓷器 5/青铜 3),GT 从 image_index.json 映射生成
  (零人工标注),复用真实链路(api.vision._recognize → _prepare_vision_query
  → 逐查询检索去重合并 top-8,与 _retrieve_and_merge 同口径),零 LLM。
  契约:**混合模态 AnyHit@8 = 100%(15/15)、识别正确率 100%**
  (跨照片识别——每器物取第 2 张,非索引自图)。耗时 ~3 分钟。
  过程发现:河南爬虫目录存在跨器物字节级重复图(妇好鸮尊/27.jpg ==
  青铜神兽/20.jpg,MD5 相同→CLIP 距离 0 并列),末张图取样 3 个 MISS
  全部为此数据质量噪声,非识别失败——已记录在 eval 注释。
  已知边界:评测面仅覆盖"库内器物不同照片",库外新器物图无法从映射表
  取 GT(需人工标注集,见下条)。
- 🟡 **补描述后 faithfulness 未重跑**:最近 eval 都是 retrieval-only,
  judge 全量在补描述之前。
- 🟡 **评测集规模小**:28 + 13 条,数据可信度有限。

  验证:185 passed + 检索契约 100%/0.693 + 混合模态契约 15/15 不变。

## 优先修复建议(按面试杀伤力)

1. **CLIP 文找图进检索排序**——多模态 RAG 叙事与"文本 RAG + 图片装饰"
   的分水岭。方案:
   - CLIP 命中作为独立 `clip` 路参与 RRF(带评测保护——先跑通再调权重);
   - 或对视觉类 query 做意图分流(CLIP 命中高置信时用其 source 反查
     文本块扩召回)。
2. **混合模态评测集**——vision 路(图+文)的 10-15 条标注数据,把
   "多模态真实场景"纳入 eval 契约。

其余(视觉定位、原生多模态编码)是行业级前沿,面试讲清"为什么不做"
(成本/场景收益)即可,不算硬伤。
