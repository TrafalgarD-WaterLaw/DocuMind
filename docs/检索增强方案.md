## 1. 入库侧假设性问题生成（Q-to-Q 映射）

**核心思想（用户修正版）：** 用户在检索时多以疑问句提问，而知识库存的是陈述句，存在"语义鸿沟"。因此在**入库时**由 LLM 为每个 chunk 生成用户"可能问什么"的假设性问题，查询时在问题索引上做 **Q-to-Q 匹配**——比正向 HyDE（LLM 写假设答案再搜）更准，因为用户问题与假设问题天然同构。

```
入库时:
  chunk "景德镇-青花梅瓶 / 釉层特征: 釉层肥厚，白中泛青..."
    → LLM 生成 3 个假设问题:
      "宣德青花梅瓶的釉层有什么特点？"
      "青花瓷釉面白中泛青是怎么回事？"
      ...
    → 写入 questions collection (metadata.source_chunk_id 指向原 chunk)

查询时:
  "宣德青花的釉层特征" → questions 索引检索 → 命中第 1 个假设问题
    → 经 source_chunk_id 映射回原始 chunk → 参与 RRF 融合
```

**实现：** `backend/src/services/retrieval/hypothesis.py`
- `generate_questions_for_batch(llm, batch)` — 每批 3 个 chunk，LLM 输出 JSON 后容错解析
- `build_question_index(llm, doc_store, questions_store)` — 全量构建，`skip_existing` 断点续跑
- 脚本：`backend/scripts/generate_questions.py [--limit=N]`（支持小批量验证）

**数据规模：** 469 chunks → ~1400 个假设问题（BGE 向量化后存 Chroma "questions" collection）。

## 2. 树状层级剪枝降噪

**问题：** 用户问"宣德青花釉层"，扁平检索会召回"宣德时期的政治背景"等语义相近但不相关的段落。

**方案：** 数据天然呈三层树状（窑口 → 器物 → 鉴定维度），先粗筛定位"相关枝干"，再只在保留枝干内细搜：

```
用户问 "宣德青花的釉层特征"
  ├─ 层级 1: 全库粗搜 top-k → 统计命中的 kiln 集合 → {"宣德"}
  ├─ 层级 2: where={"kiln": {"$in": ["宣德"]}} 细搜 → 统计 artifact 集合
  ├─ 层级 3: where={"$and": [{kiln...}, {artifact...}]} 细搜 → 具体釉层段落
  └─ 结果带 pruned_path 标注（可解释）
```

**实现：** `backend/src/services/retrieval/tree.py`
- 基于 `VectorStore.retrieve(where=...)` 元数据过滤（Chroma 原生支持）
- 多层级条件用 `$and` 组合（Chroma where 顶层只允许单个条件）

## 3. 三路召回 + RRF 动态融合 + 图谱锚定

```
用户问 "宣德青花与元代青花釉层的区别"
  │
  ├─ 路1 semantic: 原始 chunks 向量检索 (Chroma documents)
  ├─ 路2 question: 假设问题索引 Q-to-Q → source_chunk_id 映射回原文
  ├─ 路3 bm25:     jieba 分词 + BM25 关键词精确匹配
  └─ 路4 graph:    实体提取(LLM) → Neo4j 关联节点 → 扩展查询词 → 补一轮语义检索
                    （Neo4j 不可用时快速失败降级，不影响其他路）
  │
  ▼
RRF 融合 (k=60): score(doc) = Σ 1/(k + rank_i)
  → 结果带 paths 标注（哪些路命中，可解释召回来源）
```

**实现：** `backend/src/services/retrieval/hybrid.py`
- `HybridRetriever.retrieve(query)` — async，四路并行召回 → `_rrf_fuse` → 排序
- 快速失败：Neo4jStore 连续 2 次连接失败标记不可用（`providers/graph/neo4j.py`），
  避免每次查询触发驱动指数退避（最长 30s 重试）

## 4. 证据锚定与可解释生成

```
Step 1: HybridRetriever 召回 → 文档编号 [1][2][3]...
Step 2: 发送 sources 流式事件（前端渲染可点击引用卡片）
Step 3: prompt 要求"引用知识库信息时在句末标注 [N]"
Step 4: LLM 流式输出: "宣德青花釉层肥厚[1]，与元代钴料发色不同[3]"
Step 5: 前端解析 [N] → 点击弹出原文卡片（结论-证据双向索引）
```

**实现：** `services/agent/orchestrator.py::quick_answer`
- 修复原检索 bug（dict 访问 `d.page_content` → AttributeError 静默失败）
- 新增 `StreamEventType.SOURCES = "sources"` 事件（`models/response.py`）
