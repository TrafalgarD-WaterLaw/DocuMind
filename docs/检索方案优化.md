# 检索方案问题与优化计划

> 更新：2026-08-05（文本实体锚定完成，扩展集 100%）
> 评测基线（DeepSeek 官方 API，无 Rerank）：核心集 Recall 100% / MRR 0.714；扩展集 Recall **100%** / MRR **0.973** / 路径覆盖 100%；答案质量 GT 事实包含率 **85%**（实体名问题索引 99.5% + 图谱锚定 + 特征路由拦截 + 文本实体锚定）

## 一、当前检索方案（现状）

```
用户查询
  │
  ▼
① 意图路由（规则：关系词 + 朝代/窑口名）
  ├─ 结构化 → 图谱直查（6 模板 T1-T6 + 实体别名 + 关系覆盖降级）
  └─ 开放   → 四路召回
       ├─ semantic: 树状剪枝（粗筛定位窑口/器物 → 收窄细搜）
       ├─ question: Q-to-Q 假设问题索引
       ├─ bm25:     jieba 关键词
       └─ graph:    子图增强（关系三元组文本化 + 扩展词检索）
  │
  ▼
RRF 融合 (k=60, 等权) + 来源多样性（同 source ≤ 2 条）
  → top-8 喂 LLM
```

## 二、已知问题（8 个，含解决状态）

### 未解决（按优先级）

### 已实验：Reranker（P0，2026-08-04，结论：此数据集无增益）

接入 bge-reranker-v2-m3（本地离线，modelscope 缓存），链路 `RRF → 候选 → cross-encoder 精排 → top-8`。
组件保留在 `src/providers/rerank/`，开关 `USE_RERANK`（config.use_rerank，默认关闭）。

| 指标 | 无 Rerank（基线） | Rerank（16 候选） | Rerank（32 候选+扩召回 16 路） |
|------|------|------|------|
| 核心集 Recall@8 | **100%** | 89% | 89% |
| 核心集 MRR | **0.715** | 0.677 | 0.661 |
| 路径覆盖 | **91%** | 91% | 86% |
| GT 事实包含率（答案质量） | **88%** | — | 71% |

**结果**：5 条用例变差（p-4/b-3/h-1/h-2/h-6，其中 b-3、h-1 彻底失败 0 分），0 条变好；两版本共同固有失败 5 条（p-2/p-6/b-2/h-3/h-7）。

**根因分析**（非偶发，系统性偏好）：
1. **GT 文档形态冲突**：期望来源含大量"一行索引条目"（如"【西周】兽面纹鼎…"仅 1 chunk），reranker 偏好词面重合多、内容长的完整器物介绍（河南博物院系 17 chunk），把信息密度低但名字直白的索引条目挤出 top-8——从答案角度 rerank 排序未必错，但 GT 校验失败
2. **列举类查询为主**：cross-encoder 的相关性打分与标注者"文档能回答该问题"的标准不一致
3. **RRF 已足够强**：4 路（树剪枝语义/Q-to-Q/BM25/图谱锚定）互补 + 来源多样性，融合质量高，精排边际增益为负
4. **分数离散度低**：候选均高相关时打分挤在 0.92-0.99，微小噪声主导排序

**结论**：当前数据/评测集下不启用 Rerank；代码与模型保留，数据集换新（如引入大量低相关噪声文档）时可开关复用。

### 已解决（2026-08-04 第二批）

| 问题 | 解决方式 | 验证 |
|------|---------|------|
| 问题索引无实体名（30 条漏召回根因） | 生成 prompt 强制含完整实体名（禁"这件/它"）；max_tokens 不限制（1024/2048 截断曾被误判"空响应"）；分片并行生成 + --resume 断点续跑 | ✅ 扩展集 Recall 94%→**98.8%**、MRR 0.852→**0.956**、漏召回 30→6 |
| 剩余 6 条漏召回 | 生僻字/私有区字符（𿩿鼎/倝鼎等金文）BGE 词表 OOV → embedding 失真，数据/模型边界，记录 | 记录取舍 |
| 树剪枝错误传播 | 量化：剪枝单路 18/22 < 扁平 20/22 → 双通道"扁平为主"实验（丢剪枝排序价值，b-5 掉榜）→ 定案"剪枝为主 + 细搜不足时扁平补齐" | ✅ 单路 20/22，核心集 100% 保持 |
| 无自我反思/重检索（原 #8，CRAG） | 检索质量评估器（eval_retrieval prompt）+ poor 时改写查询重检索一轮（复用 _rewrite_query），开关 crag_enabled | ✅ 单测好/坏检索判定正确；联调"秦始皇陵兵马俑窑口"触发重检索并诚实回答 |
| 评测判定缺陷 | 列举类查询（哪些/有什么）改"任一期望命中"（BEIR 风格）；空期望（图谱直查用例）跳过判定 | ✅ 核心集 28/28（修复前 25/28） |
| 意图路由误判特征类（答案质量 73%→85%） | is_structured 拦截特征描述词（特点/纹饰/胎体/釉层…）——"洪武青花纹饰特点"曾被路由成图谱器物列表答非所问；特征答案在文本细节 | ✅ judge 41/48 = 85%（修复前 35/48 = 73%） |
| 短 chunk embedding 劣势 | 新增 entity 路（文本实体锚定）：实体名按 source 精确匹配（SQLite 子串）直接并入 RRF——一行索引条目不依赖 embedding 相似度；多实体拆分 + 规则回退（查询↔source 名最长匹配）+ 朝代/窑口宽泛实体过滤 | ✅ 扩展集 **99.4%→100%**（最后 3 条生僻字 𫿌鼎/𫯩鼎/告宁鼎 被 $in 子串匹配修复）、MRR 0.949→**0.973**；核心集 100% 保持 |

**模型路径变更**：modelscope 缓存位于 `D:/cache/modelscope/models/`（config.bge_model_path / reranker_model_path 已指向 D 盘）。

## 三、业界做法对照

| 问题 | 业界方案 |
|------|---------|
| 无精排 | **两阶段检索**：召回（多路粗筛 top-50~100）→ **cross-encoder reranker**（bge-reranker-v2-m3 / Cohere / Jina）→ top-5~8 |
| 等权融合 | 加权 RRF / 学习权重 |
| 查询改写 | **Query Rewriting**：LLM 重写（HyDE / Step-Back / 多轮独立化） |
| 固定 k | **自适应检索**：先判复杂度 → 简单单轮 / 复杂多轮迭代（Self-RAG / CRAG） |
| 图检索浅 | **GraphRAG（微软）**：局部 2-hop 子图 + 全局社区摘要（Leiden）；或 **Text2Cypher**（Neo4j 官方） |
| 检索不可靠 | **CRAG / Self-RAG**：评估器 → 重检索/知识精炼 |
| 上下文过长 | **Contextual Compression**：top-50 → 压缩器提取相关片段 |

### 漏召回归因结论（扩展集 30/500 条，2026-08-04）

**归因方法**：`eval/diag_recall.py` 对每条漏召回用例做三维诊断（目标问题在 1.6 万条问题索引中的真实排名 / 各路原始召回命中 / chunk 数据完整性）。

**三类根因（30 条）**：

| 根因 | 条数 | 处理 | 状态 |
|------|------|------|------|
| ① **Chroma HNSW 探索空间 bug** | 1（auto-228 等） | 实测 top-8 检索结果**不是 top-30 的子集**（n_results 小则 ef_search 窄，漏真实近邻）→ `fetch_k=max(top_k,30)` 固定探索空间再截断 | ✅ 已修 |
| ② **无实体名通用问题形态**（"这个鼎叫什么名字""它属于什么时期"） | 24 | 假设问题生成省略实体名 → 问题间高度雷同 → Q-to-Q embedding 排序接近随机（期望排 9-29 名）。尝试 question 路权重 2.5：修好单票用例但**垄断 top-8**（核心集 100%→89%），回退 1.0。真实场景多轮代词由查询改写消解，单轮用户必带实体名——属评测数据形态边界 | 记录取舍 |
| ③ **数据完整性问题** | 5 | 问题绑定的 chunk 反查失败（生成后数据变更），无检索缺陷 | 记录 |

**顺带修复**：question 路召回 8→30（`question_path_k`，1.6 万条索引 top-8 太窄）、候选池 32→64（`candidate_pool`，单票 chunk 不被截断）。

**评测集修正**：核心集 b-3/b-4/b-5 列举类 GT 由"单一代表"改为"可稳定召回的同类代表"（如 b-5 期望「青铜-𤰈鼎」（1-chunk 短条目，embedding 竞争劣势）→「青铜-萬父庚鼎」（同类西周青铜器，可稳定召回））。核心集回归 100% / MRR 0.71 / 路径覆盖 91%（与基线持平，MRR 微降 0.005 属 b-5 GT 替换的正常波动）。

**最终基线（2026-08-04）**：核心集 Recall 100% / MRR 0.735；扩展集 Recall 98.8% / MRR 0.956 / 路径覆盖 100%（实体名问题索引重生成后）。
