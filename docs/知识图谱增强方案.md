# 知识图谱增强方案（细化设计）

> 状态：设计完成，待实现
> 目标：把图谱从"检索词来源"升级为"结构化问答引擎 + 关系上下文"

## 一、总体架构：路由分工 + 子图增强

```
用户查询
  │
  ▼
① 意图路由（规则优先 + LLM 兜底）
  ├─ 结构化问题 → ② Text2Cypher 模板直查图谱 → 结构化结果
  └─ 开放问题   → ③ 现有四路召回（向量/Q-to-Q/BM25/图锚定）
                    └─ 图锚定升级为「子图增强」：2-hop 关系上下文
  │
  ▼
④ 证据锚定生成（统一：结果编号 [N] → 引用可溯源）
```

## 二、① 意图路由设计

### 判断规则（零成本，先于 LLM）

```
结构化信号（任一命中 → 结构化）:
  1. 查询含朝代/窑口名（规则匹配图谱 Era/Kiln 节点名，已有）
  2. 查询含关系词: 出土/属于/现藏/分布在/哪些/多少/共几件/存于
  3. 查询是"实体+属性"模式（X是什么朝代/出土于哪里/藏于哪里）

开放信号 → 走四路:
  特点/特征/工艺/纹饰/风格/为什么/如何/比较/区别
```

### 兜底

规则未命中（如"叩鼎的信息"）→ LLM 判断一次（复用 `agent_intent` 思路，新增 `query_type` 字段）。

## 三、② Text2Cypher 模板设计（安全可控，非自由生成）

**原则**：不自由生成 Cypher（防注入 + 防语法错误）。预定义模板 + LLM 只填槽位。

### 模板集（6 个）

| # | 模板 | 适用问题 | 参数 |
|---|------|---------|------|
| T1 | `MATCH (a:Artifact {name:$n}) RETURN a` | "X 是什么/在吗" | 器物名 |
| T2 | `MATCH (a:Artifact {name:$n})-[r]->(t) RETURN type(r), t.name` | "X 属于什么朝代/出土于哪里/属于哪个窑口" | 器物名 |
| T3 | `MATCH (e:Era {name:$e})<-[:BELONGS_TO]-(a:Artifact) RETURN a.name LIMIT 20` | "商代有什么青铜器" | 朝代名 |
| T4 | `MATCH (k:Kiln {name:$k})<-[:BELONGS_TO_KILN]-(a:Artifact) RETURN a.name LIMIT 20` | "宣德窑有什么瓷器" | 窑口名 |
| T5 | `MATCH (s:Site {name:$s})<-[:EXCAVATED_AT]-(a:Artifact) RETURN a.name LIMIT 20` | "X遗址出土了什么" | 遗址名 |
| T6 | `MATCH (a:Artifact)-[:BELONGS_TO]->(e:Era {name:$e}), (a)-[:EXCAVATED_AT]->(s:Site) RETURN a.name, s.name LIMIT 20` | "商代器物分布在哪些遗址"（全局聚合） | 朝代名 |

### 模板选择流程

```
LLM 输出: {"template": "T2", "entity": "叩鼎"}   ← 槽位提取（max_tokens 小）
模板校验: 模板号白名单 + entity 非空 + entity 长度 < 30
执行 → 结果格式化为文本:
  "【图谱】叩鼎 —[BELONGS_TO]→ 商代；叩鼎 —[EXCAVATED_AT]→ 安阳殷墟"
```

### 槽位提取 prompt（新增 `graph_cypher.md`）

```
## SYSTEM
判断查询适用的图谱查询模板（仅限 T1-T6）并提取实体名。
只输出 JSON: {"template": "T2", "entity": "叩鼎"}
实体不存在输出 {"template": "none", "entity": ""}

## USER
查询: {query}
可用模板: {templates}
```

## 四、③ 子图增强设计（图锚定升级）

### 现状 → 升级

```
现状: 实体 → search_path 邻居名 → 拼入扩展检索词（信息损失）
升级: 实体 → search_path 邻居 + 关系 → 关系三元组文本化
      → 作为「图谱上下文块」进 prompt（不丢失关系语义）
```

### 图谱上下文格式

```
【图谱关系】妇好鸮尊 —[BELONGS_TO]→ 商代
【图谱关系】妇好鸮尊 —[EXCAVATED_AT]→ 安阳殷墟妇好墓
【图谱关系】妇好鸮尊 —[关联]→ 妇好墓玉龙
```

### 接入方式

1. 结构化路径：Cypher 结果直接作为 sources 事件条目（`source: "图谱: 叩鼎 —[BELONGS_TO]→ 商代"`）
2. 开放路径：子图增强结果作为**第 5 条证据**进 sources（`paths: ["graph"]`），与四路结果一起编号
3. 前端零改动（sources 渲染已通用）

## 五、完整配合流程（示例）

```
Q: "商代青铜器主要分布在哪些遗址？"

① 路由: 含"朝代名(商代)"+"分布" → 结构化
② T6 模板: MATCH 商代 → BELONGS_TO 器物 → EXCAVATED_AT 遗址
   结果: 【图谱】叩鼎→安阳殷墟；兽面纹鱼形扁足鼎→大洋洲商墓；...
③ 无四路检索（结构化问题不需要文本检索）
④ 生成: 以图谱结果 + 图谱上下文为证据 → 回答带 [1][2] 引用
```

```
Q: "妇好鸮尊的纹饰有什么特点？"

① 路由: "特点" → 开放
② 四路召回（现有）
③ 子图增强: 妇好鸮尊 → 商代 + 妇好墓玉龙（关系上下文进 prompt）
④ 生成: 散文证据 + 图谱上下文 → 回答"雷纹衬地…[1]" 
        + "同出土地器物: 妇好墓玉龙[图谱]"
```

## 八、风险与边界

- 模板覆盖有限：复杂关系问题（跨 3 跳）需扩展模板，不自由生成
- 实体名匹配：图谱 name 是"窑口-器物"格式（瓷器），槽位提取后需尝试 [原名, 窑口-原名] 两种匹配
- 图谱不可用时：结构化路由降级为开放四路（现有降级机制）
- 意图路由误判：规则未命中时 LLM 兜底 + 结构化失败自动降级文本检索
